# 组内最高评分（Best-in-Group）标识 · 分析与方案评估

> 基于源码审计（`CanvasImageItem.ts` / `InfiniteCanvas.tsx`）。
> 结论先行：当前标识在**逻辑层是健全的**，问题全在**表现层**——皇冠埋在条件苛刻的信息行内，对比变量过多，违反 PRODUCT.md「一眼决策：200ms 内被理解」。

---

## 1. 现状实现（事实链）

**判定逻辑**（`InfiniteCanvas.recomputeBestInGroup`）：组内 `focusScore` 最高者胜出，严格大于（同分取先算出者）；分数后台异步逐张到达，bestHash 随新分数**静默迁移**。

**视觉呈现**（`CanvasImageItem._buildSegments`）：唯一标识是信息覆盖层底部行内的 FontAwesome 皇冠 glyph（`\uf521`），11px，颜色 `rgba(251,191,36,0.65)`，后接评分数字（绿 ≥85 / 黄 ≥50 / 红 <50）。非最优项同位置显示 60% 白色 `★` + 评分。

**显示条件链**（全部满足才可见皇冠）：
1. 设置中「图片信息」开关 ON
2. 该图 focusScore 已算出（异步，可能永远为 null）
3. 缩略图在当前缩放下信息层未被挤掉

**画布角位分配现状**：

```
┌─────────────────────┐
│ [组3]（仅首图）   (✓选中) │  ← 左上=组标签 badge，右上=选中勾 badge
│                     │
│  (照片)              │
│                     │
│ f/2.8 1/500 ISO400  │  ← 底部信息层（条件显示）
│ 👑87★82★65·········  │     皇冠/★ 埋在 EXIF 行第 5~8 个字符位
└─────────────────────┘
```

---

## 2. 问题诊断

| # | 问题 | 违反原则 |
|---|---|---|
| ① | **可见性链过长**：皇冠依赖「信息开关 ON + 分数已到」双重条件；关掉信息层（纯净浏览时）最优标识完全消失 | 功能即所见 |
| ② | **不是标识是字符**：11px、65% 透明度、埋在 EXIF 行中段，扫描一组照片时无法形成「找皇冠」的视觉搜索路径 | 一眼决策（200ms） |
| ③ | **对比信号混乱**：最优=皇冠+绿/黄/红数字，非最优=★+绿/黄/红数字。glyph、颜色、数字三变量齐变，用户在做解码而非识别。「最优但只有 72 分」时皇冠+黄数字自相矛盾 | 一眼决策 |
| ④ | **迁移无反馈**：分数异步到达导致 bestHash 迁移时，皇冠在两张之间瞬间跳变，无任何过渡 | 零等待交互的反面：无反馈变更 |
| ⑤ | **★ 语义错位**：非最优项的 ★ 读作「收藏/评级」，实际只是分数前缀装饰，制造噪音 | 每个信号须有意图 |
| ⑥ | **组级缺位**：胶片条导航时无法预知「这组的最优我选没选」，要逐组进入才能确认 | 收放自如 |

## 3. 候选方案评估

### 方案 1：独立角标徽章 ★推荐
皇冠从信息行**提取为常驻角标**：圆角徽章底（复用 `--color-canvas-badge-bg`）+ 全透明 amber 皇冠，不依赖信息层开关。bestHash 迁移时带 120ms easeOutQuart 缩放淡入（复用现有 hover 补间机制）。行内皇冠同时移除（信息行只剩纯分数，见方案 2）。

- **位置选择**：右上被选中勾占、左上有组标签（仅首图）。推荐**左上角**——非首图直接可用；首图则排在组标签右侧同行。徽章绘制模式与 `_drawGroupBadge`/`_drawSelection` 完全同构，实现路径现成
- **成本**：低-中（CanvasImageItem 增加 `_drawBestBadge` + 迁移动画，约 80 行）
- **风险**：与选中勾同图出现时双角标，需视觉对账（一中性蓝一琥珀，语义不冲突）
- **解决**：①②③④

### 方案 2：行内信号降噪（顺手做）
非最优项的 `★` 前缀**直接删除**（纯分数数字+分档色已足够）；最优项行内不再重复皇冠（已被方案 1 取代）。信息行从「glyph 动物园」变回纯数据。
- **成本**：极低（`_buildSegments` 删两个分支）
- **解决**：③⑤

### 方案 3：边框/底色高亮（排除）
最优项加 amber 内边框或角部三角。与选中蓝边框双框叠加必然打架，且「边框=选中」是已建立的系统语义，再加一种边框语义破坏一致性。**排除**。

### 方案 4：胶片条组级标记（可选增强）
胶片条项加一个小皇冠点：该组最优图已被选中时显示绿点/未选显示 amber 点，让用户在组级导航一眼知道哪组还没收最优。
- **成本**：低（FilmstripItem 有 thumbnail + 角标位；需把 bestHash+选中态映射传到胶片条，store 层有小改）
- **解决**：⑥。独立于方案 1/2，可后做

---

## 4. 推荐路线

| 步骤 | 内容 | 成本 |
|---|---|---|
| 1 | 方案 1：左上角常驻皇冠徽章 + 迁移补间 | ~半天 |
| 2 | 方案 2：行内 ★/皇冠清除，纯分数 | 10 分钟，随方案 1 同改 |
| 3 | 方案 4：胶片条「最优已选」状态点 | ~半天，可后置 |

**迁移动画细节**（方案 1 的手感关键）：旧主淡出 120ms、新主缩放回弹（scale 0.6→1，easeOutQuart 120ms）——让「分数算完后皇冠落定」成为可感知事件，而非静默跳变。reduced-motion 下即时切换。

**评分未到齐时的兜底**：组内无任何分数 → 无皇冠（现状语义保留）；全组同分 → 维持「先算出者」现状，不为同分引入新视觉。

---

## 5. 明确不做

- 不做 Top3/前三名标识：选片是每组留一，多名次制造决策噪音
- 不做分数数字角标化（把 87 直接钉在角上）：分数是相对工具不是绝对标准，角标只表达「组内最优」这一个布尔结论
- 不改 bestHash 判定逻辑（严格大于、先算优先）：逻辑层没有投诉依据
- 不引入新的颜色：徽章用既有 amber 语义（`--color-canvas-badge-bg` 底 + amber glyph），不动令牌
