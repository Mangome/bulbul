Bulbul · 设计治理提案

界面与动效：从「各自为政」到「一套语言」

现状审计发现：视觉令牌（variables.css + DESIGN.md）已经成体系，真正零散的是动效层——三套并行的动画系统、11 种时长、7 条缓动曲线，每个组件自己发明入场方式。以下三套静态页方案，差异不在皮肤，而在动效性格的统一策略。

一、问题诊断（基于源码审计）

① 三套动效系统并行

CSS transition（令牌化）、motion JS 库（8 个组件）、Canvas 2D 手写补间（easeOutQuart）。同一类交互（如对话框入场）在不同页面走不同系统，手感无法统一。

② 时长失控：11 种取值

令牌只定义 120 / 200 / 300ms 三档，实际代码出现 80、120、150、180、200、240、250、260、280、300、500ms。JS 侧硬编码 duration: 0.15 / 0.18 / 0.24 / 0.28，全部偏离刻度。

③ 缓动失控：7 条曲线

令牌 4 条（standard / out-quint / swift / bounce），代码另造 3 条：easeOutQuart、cubic-bezier(0.16,1,0.3,1)（Loupe）、'easeOut'（Toast）。DESIGN.md 明令「禁止自由发挥」，实际人人发挥。

④ 名实不符 + 重复定义

EASE_OUT_QUART 常量在两个对话框里各抄一份，其值 [0.25,1,0.5,1] 其实就是令牌的 --ease-swift——名字叫 quart，值是 swift，令牌里的 out-quint 几乎没人用。

二、三套解决方案

方案 A · 收敛方案 B · 暗房纪律方案 C · 灯箱策展
策略视觉不动，只收编动效层深色优先，动效做减法到极致把 spring/stagger 扶正为官方语言
时长档120 / 200 / 300ms120 / 240ms 两档120ms + 统一 spring
缓动3 条（standard/out-quint/swift）2 条（禁用 bounce）2 条 + 1 组标准 spring 参数
编排禁止 stagger，入场统一 200ms只剩 fade，无位移stagger 40ms 写入规范
改动成本低：改令牌引用，删硬编码中：重做主题 + 砍动效中高：重排视觉 + 统一 spring
风险几乎为零深色需全量回归对比度spring 滥用风险需护栏
适合当前版本快速止血 ● 推荐专业暗房工作流定位强化「策展灯箱」品牌叙事
方案 A

收敛 · Token Lock

不动一丝视觉，把 11 种时长、7 条曲线收进 3×3 令牌矩阵。motion 库降级为「仅 AnimatePresence 场景」，其余全部回归 CSS 令牌。

成本最低 · 2~3 天收敛全库
 方案 B

暗房 · Darkroom Discipline

纯黑画布、chrome 极致退后、闲时自动隐藏面板。动效只做 fade，两档时长两条曲线，删掉全部弹性与错落——相机的冷静。

定位向 · 专业工具气质最强
 方案 C

灯箱策展 · Light Table

兑现 DESIGN.md 的「策展灯箱」隐喻：暖纸面、编辑排版，把 spring 与 stagger 从野生状态扶正为唯一官方入场语言。

品牌向 · 叙事感与温度最强
